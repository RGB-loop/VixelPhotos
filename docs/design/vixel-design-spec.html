Vixel · UI 设计规范 v1 · 2026-10

从"能用的搜索框"到一个本地媒体资料库应用

Vixel 现在能检索图片、视频和音频，界面却还是一个标题栏加一个网格。这份规范定义新的窗口结构（侧边栏 + 工具栏 + 检查器 + 状态栏）、一套语义化 token，以及按阶段迁移的顺序。参考的是 Apple Photos、Lightroom、Eagle、Finder、DaVinci Resolve 和 Immich 的成熟做法。

适用：src/renderer基准平台：macOS 15 / 26状态：草案，待评审
提案

新的窗口结构

结论：要侧边栏，也要状态栏。侧边栏统一"在看什么"（资料库 / 类型 / 地图 / 人物 / 文件夹 / 搜索），工具栏只放"对当前内容做什么"，状态栏负责计数、后台活动和缩略图尺寸。检查器（右栏）可随时收起。

侧边栏 · 232 px，可拖 200–320"看什么"的唯一入口。现在标题栏里的 照片/地图/人物 和 全部/图片/视频/音频 两组按钮都并进来，所以"图片"这个词只在这里出现一次。⌘⌥S 收起。

2

工具栏 · 52 px左侧是当前来源的名称和数量，然后是筛选 chip、搜索框和检查器开关。红绿灯固定在侧边栏顶部，侧边栏收起后移到工具栏最左。

3

检查器 · 272 px显示选中项的预览、元数据、片段时间轴和相似内容。⌘I 开关。全屏详情页仍然保留，只用于看大图和播放。

4

状态栏 · 26 px左边是计数和选择数，中间是后台活动（点击打开"活动"面板），右边是缩略图尺寸滑块（同 Finder）。

5

内容区网格里有选中态（2 px accent 描边），支持方向键、空格快速查看、↩打开详情，多选用 ⌘/⇧ 点击。

现状审计

为什么需要一套规范

对 src/renderer 当前代码的统计。问题不是哪个页面"丑"，而是每个组件各自选值，没有共同的约束。

15 级白色透明度：white/5 到 white/90，靠目测挑值，没有语义
6 种字号，包括 9px（低于 macOS 最小 10 pt）和只用过一次的 13px
5 种圆角，同类控件用的圆角也不一样
0语义色 token。失败用 red-400/70，accent 同时被拿来当"成功"和"选中"
  • 信息架构：标题栏同时放视图切换、搜索、类型过滤、日期和设置，两组分段控件挤在一起，"照片 / 图片"撞名就是这么来的。
  • 没有选中态：网格只能点开，不能先选再看信息，也没有批量操作的基础。
  • 原生集成缺失：没有自定义应用菜单（Menu.setApplicationMenu 未调用），快捷键在菜单里找不到；没有右键菜单。
  • 设置是模态弹窗：文件夹、模型和扫描入口都在一个 512 px 的对话框里，应该改成独立的设置窗口（⌘,，带分页标签）。

Token · 颜色

语义颜色

组件只引用语义名，不直接写 white/30。文字、线条、填充各自只有几档，挑不到合适的值时应该新增一个语义 token，而不是临时写一个数字。

组件

媒体卡片：四个角各有固定用途

每张卡片的角标位置固定，扫视时眼睛知道去哪里找。悬停的操作按钮只出现在上方两个角，下方两个角始终留给信息。

#3☆命中 1:04▶ 2:18
左上排名，仅在搜索结果的信息式网格中显示
右上悬停操作：收藏、更多（⋯）
左下搜索命中的时间，accent 底色
右下类型图标 + 时长，等宽数字
  • 底边细线：视频悬停预览时显示播放进度，选中命中片段时标出片段在全长中的位置。
  • 状态："索引中 / 失败 / N 份重复"不再放在卡片上，移到检查器。卡片只保留和浏览相关的信息。
  • 两种密度：沉浸式（默认浏览，只显示时长）和信息式（搜索结果，四个角全部显示），按 G 切换。
  • 音频卡片：显示封面或 accent 色波形，悬停不自动播放，按 空格 才播放。
组件

后台活动分三层

索引会跑几个小时，进度信息要能看到但不打扰。三层逐级展开，同一份数据在每一层的详细程度不同。

层级位置内容
被动侧边栏文件夹行正在索引的文件夹显示 accent 色小圆点，有失败时显示红色计数
概要状态栏中间细进度条 + "视频片段 12/86 · 约 14 分钟" + 失败徽标；空闲时显示"已是最新"
明细活动面板（现在的 TaskDrawer）按队列列出待处理、进行中和失败；可暂停、重试、清除。由"任务"改名为"活动"，入口也可以放在菜单"窗口 → 活动 ⌘⌥A"

落地

迁移顺序

每一阶段单独提交，做完都能直接用。第一阶段只换 token 不改结构，视觉回归风险最低。

P0

Token 化

在 tailwind.config 里定义语义色（text-primary、bg-raised、line-border…）、字号阶梯和圆角，再用 codemod 把 15 级 white/xx 收敛到语义类上，同时去掉 9 px 字号。界面结构不动。

P1

窗口结构

侧边栏（资料库 / 浏览 / 文件夹）、52 px 工具栏、状态栏（计数 + 活动 + 尺寸滑块）。标题栏里两组分段控件删除。加上原生应用菜单和快捷键。

P2

选中、检查器、右键菜单

网格支持单选和多选，⌘I 打开检查器，空格快速查看，右键菜单（在 Finder 中显示、查找相似、复制路径）。全屏详情页的侧栏改为复用检查器组件。

P3

搜索作为一等公民

侧边栏"搜索"分组（最近 / 已保存），设置改为独立窗口，网格密度切换，视频悬停时按鼠标位置拖动预览（索引阶段生成 sprite）。浅色模式另外评估。

需要拍板的两点：① 侧边栏的"资料库"分组是否直接取代顶部的 照片/地图/人物 切换（本规范的建议是取代）；② 设置是否在 P1 就拆成独立窗口，还是等到 P3。
