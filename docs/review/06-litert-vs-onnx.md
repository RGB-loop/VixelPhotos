# EmbeddingGemma 2：LiteRT vs 旧 ONNX，结果为什么不同、是否符合预期

结论：**差异来自量化方式、图像预处理和文本前缀，都是预期内的；LiteRT 的检索质量明显更好，并且与旧向量不可混用（必须重建索引）。**

## 方法

- 同一个模型（EmbeddingGemma 2，768 维），两套推理：
  - 旧：transformers.js 4.3.1 + onnxruntime CPU，`onnx-community/embeddinggemma-2-ONNX`，文本/视觉 q4、音频 q8（训练后量化），代码取自 `49bfe91^:src/core/embedding/providers/gemma2Provider.ts`。
  - 新：LiteRT-LM 0.18.0，官方 `embeddinggemma-2-740m.litertlm`（文本 int4、视觉 int8、音频混合，均为 QAT 量化感知训练），GPU。
- **两边输入逐字节相同**：演示库 31 张图片统一解码成长边 1024 的 JPEG；3 段视频按索引流程抽帧（每 4 s 一帧、≤8 帧、长边 512）+ 32 s 音轨。
- 检索质量：26 个人工标注的查询（中英文，含“海边”“冰雪”这类多答案查询），对 34 项按余弦排序，算 MRR、Recall@5、mAP。不经过相关性门槛，纯比较排序。
- 复现脚本：`/tmp/eval/{prep,litert,score}.cjs`、`/tmp/onnx-ref/encode.mjs`（临时环境，未进仓库）。

## 向量一致性（同一输入，余弦）

| 模态 | 最小 | 中位数 | 最大 |
|---|---|---|---|
| 文本（同一前缀） | 0.975 | **0.987** | 0.991 |
| 图片 | 0.924 | **0.957** | 0.976 |
| 视频片段（帧 + 音频） | 0.942 | **0.951** | 0.960 |

LiteRT 内部单独改一个因素：

| 改动 | 中位数余弦 |
|---|---|
| 文本前缀 `task: query` → 官方 `task: search query` | 0.994 |
| 图片每张 140 → 70 个视觉 token | 0.974 |
| 视频片段去掉音轨 | 0.967 |

## 检索质量

| 配置 | MRR | Recall@5 | mAP |
|---|---|---|---|
| ONNX（旧版，旧前缀） | 0.916 | 0.853 | 0.844 |
| ONNX + 官方前缀 | 0.946 | 0.891 | 0.872 |
| **LiteRT（现版）** | **0.981** | **0.981** | **0.974** |
| LiteRT + 旧前缀 | 0.981 | 0.974 | 0.971 |
| LiteRT 图片 70 token | 1.000 | 0.955 | 0.983 |
| 混用：LiteRT 查询 × ONNX 索引 | 0.946 | 0.878 | 0.882 |

## 解读

1. **文本几乎一致（0.987）**：同一套权重，只是量化不同；文本编码器两边都是 4 bit，差异最小。
2. **图片 / 视频差得多一些（0.95–0.96），主要两个原因**：
   - *视觉 token 数不同*：旧 ONNX 处理器每张图最多 280 个视觉 token，LiteRT 默认 140（库日志：`max_num_patches: 1260`，3×3 池化）。只在 LiteRT 内部把 140 改成 70，向量就变化到 0.974，和两个引擎之间的差距同一量级 —— 分辨率 / token 预算本身就是主要变量。
   - *量化方式不同*：旧版视觉编码器是 **训练后 4 bit**，LiteRT 是 **QAT int8**。QAT 在训练时就适应了量化误差，通常比训练后量化更接近原始精度。
3. **LiteRT 检索更好（mAP 0.844 → 0.974）**：修正文本前缀只贡献了一小部分（ONNX 0.844 → 0.872）；大头来自 LiteRT 自身（QAT 视觉编码器）。在 LiteRT 上前缀新旧几乎没差别（0.974 vs 0.971）。
4. **不能混用**：用 LiteRT 的查询去搜旧 ONNX 索引，mAP 只有 0.882，比各自配套都差 —— 所以这次切换整库重建索引是必要的。
5. **相似度分布整体偏移**：LiteRT 的图片两两相似度整体更高（真实库随机两张中位数 0.72，ONNX 约 0.68），因此“相似内容”门槛从 0.80 调到 0.85、语义相关性门槛从 2.5σ 调到 2.75σ（见 `src/core/search.ts` 注释里的标定数据）。

## 局限

- 样本小（34 项、26 个查询），只能说明方向和量级；视频只有 3 段，音轨对这几个以画面为主的查询没有影响。
- 70 token 的 MRR 更高、Recall@5 更低，差异在样本噪声范围内；默认保持 140（信息更多、速度差别不大）。
